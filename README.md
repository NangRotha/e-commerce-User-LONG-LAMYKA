# frontend-user

User-facing e-commerce storefront built with **React + Vite + Tailwind CSS v4**.

## Features

- 🛍️ Product catalog with search & category filters
- 📦 Product detail pages with sale prices & quantity selector
- 🛒 Persistent shopping cart (localStorage)
- 🚫 **No login / sign-up** — customers check out as guests (name, phone, address, optional email)
- 🔳 **KHQR scan & pay** with ABA Pay / Bakong Wallet + **auto payment detection**
- ✅ Order confirmation with live status (updates by WebSocket + polling)
- 🌐 Khmer / English language toggle, 🌓 dark / light theme
- ⚡ Real-time product, alert, slide & order updates over WebSocket

## Getting started

```bash
npm install
npm run dev
```

The storefront talks directly to the deployed backend
**`https://backend-e-online.onrender.com`** by default, so it works without
running anything locally. The Vite dev server also proxies `/api`, `/uploads`
and `/ws` to that same backend (used as a fallback / for WebSocket realtime).

### Run backend + frontend together (recommended for local backend development)

```bash
npm run dev:all
```

This starts the FastAPI backend (`uvicorn` on :8000) and the Vite frontend
(:5173) at the same time with one command. Set
`VITE_API_URL=http://localhost:8000` in `.env` first if you want the app to use
that local backend instead of Render.

### Run them separately

```bash
# Terminal 1 — backend (port 8000)
cd ../backend-e-online
.venv/bin/uvicorn app.main:app --reload

# Terminal 2 — frontend (port 5173)
npm run dev
```

Then open http://localhost:5173

## Guest checkout (no account needed)

Customers never log in. The checkout form collects **full name, phone, delivery
address, optional note** and an **optional email** (used only to send the payment
receipt). The order is posted to `POST /api/orders/checkout` **without any auth
token**, so the backend owner must have the latest backend deployed (guest
checkout support + `customer_email` column).

## KHQR payment (ABA Pay / Bakong Wallet) — scan & auto-confirm

1. After placing the order the customer lands on **Order Success** which shows a
   **KHQR code** (generated by the configured KHQRcc/ABA Pay gateway).
2. The page **polls `/api/payments/status` every 3 seconds** and, as soon as the
   gateway reports `success`, calls `/api/payments/confirm` which marks the order
   as **paid** server-side and emails the receipt.
3. The page also listens to the WebSocket `orders_changed` event, so if an admin
   changes the order status it updates instantly.
4. The QR image/URL is stored in the database, so refreshing the page (or
   re-opening the link) still shows the same QR.

Merchant details shown on the payment screen (**Company Name**, **Display
Name**, **Bakong Wallet ID**, **Currency**, **KHR rate**) are configured in the
Admin Panel → **Settings → Bakong Wallet / KHQR payment**.

> ⚠️ The `payment_currency` setting only controls how the amount is *displayed*
> (USD or KHR). The actual QR currency comes from your KHQRcc/ABA Pay gateway
> configuration — keep them consistent.


## Email settings (receipts only)

The storefront no longer has OTP or Telegram login, so email is used **only to
send the payment receipt** after a successful KHQR payment. Configure the sender
in `../backend-e-online/.env` (`SMTP_*` or `BREVO_API_KEY`) — see the
**[backend README](../backend-e-online/README.md)** for the full provider table
(Gmail / Yahoo / Zoho / Brevo / SendGrid / Mailgun).

If email is not configured, orders and payments still work — only the receipt
email is skipped.

## Environment variables

| Variable        | Description                                            | Default                                |
| --------------- | ------------------------------------------------------ | -------------------------------------- |
| `VITE_API_URL`  | Backend API base URL (used for all API + media URLs).   | `https://backend-e-online.onrender.com` |
| `VITE_WS_URL`   | WebSocket base URL for realtime updates.                | derived from `VITE_API_URL` (`wss://…`) |

Vite loads these from `.env.development` (dev) and `.env.production`
(production build). If the variable is missing or empty, the code falls back to
`https://backend-e-online.onrender.com`, so the app never breaks with a
"localhost" backend.

To develop against a local backend, create `.env.development.local`
(git-ignored) — **not** `.env`, because Vite gives `.env.development`
higher priority than `.env`, so a plain `.env` override would be ignored:

```
# frontend-user-e-online/.env.development.local
VITE_API_URL=http://localhost:8000
VITE_WS_URL=ws://localhost:8000
```

Then run the backend on SQLite (no env needed → `backend-e-online/ecommerce.db`):

```bash
cd ../backend-e-online
.venv/bin/uvicorn app.main:app --reload
# បង្កើត Admin (Storefront គ្មាន Sign Up ទៀតទេ)
.venv/bin/python create_admin.py admin@example.com --password 'admin12345'
```

For an unauthenticated dev proxy (no CORS), leave `VITE_API_URL` empty — the
Vite proxy then forwards `/api`, `/uploads` and `/ws` to the backend.
